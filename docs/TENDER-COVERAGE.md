# 标书需求转译与当前产品覆盖矩阵

> 对照基准：《2025年西湖区应急管理综合平台建设项目招标文件（挂网稿）》第三部分“采购需求”及第四部分“评标办法”。核对日期：2026-09-20。

## 1. 先把甲方需求翻译成产品语言

甲方并不是要求重新做一个孤立的网站，而是要求以原“风险普查”系统为核心，把“台汛卫士”和“城市安全综合监管”一并纳入同一平台，并新建预案中心。最终应形成统一入口、统一身份、统一权限、统一接口和统一数据规范，同时完成旧系统裁剪迁移、信创适配、等保测评、培训和一年运维。

产品可以拆成五条主线：

1. **一单位一平台**：一个入口、一个用户体系、一套授权规则、一套接入规范，三个原系统不再各自登录和各自管理账号。
2. **台汛卫士改造**：保留天气、预警、响应、值班、监测、资源、救援圈、数据管理、灾后复盘和后台管理等指定功能，删除标书明确核减的功能，并迁移原有数据。
3. **预案中心新建**：把纸面预案转成可展示、可匹配、可调整、可启动、可生成任务、可跟踪执行、可复盘优化的数字预案。
4. **城市安全综合监管改造**：保留设备、预警、移动端、可视化大屏和智慧预警，完成系统裁剪、信创云迁移和驾驶舱优化。
5. **风险普查增强**：接收多来源数据，识别新增、变更、删减，向镇街和行业部门派单确认，再把确认结果回写数据仓，并支持按类型、区域、字段筛选下载。

软件之外还有正式交付要求：建设期 6 个月、试运行不少于 1 个月、信创符合性测评、等保测评、培训和手册、7×24 小时运维、1 小时响应和 24 小时处理，以及保密、版权、验收资料和一年免费运维。

## 2. 状态口径

| 状态 | 含义 |
| --- | --- |
| 已形成闭环 | 页面、数据库、权限和主要状态流转已经存在，可在当前产品中操作和留痕 |
| 部分实现 | 有页面或基础数据能力，但尚未覆盖标书列出的全部细项，或仍是通用台账 |
| 模拟适配 | 平台内流程可以演示，但上游或下游使用模拟适配器，不能视为真实政务接入 |
| 待甲方接入 | 必须取得甲方账号、接口、旧数据、网络或第三方授权后才能完成 |
| 正式交付缺口 | 需要专项实施、测评、文档或运维组织，不能只靠增加网页功能完成 |

## 4. 当前产品进度结论

### 已经具备

- 可公开访问、登录态跨子域共享、刷新后数据库数据不丢失的 Next.js + Supabase 产品底座；
- 门户、角色、组织、账号启停、邀请码、RLS 数据权限和操作日志；
- 监测阈值到告警、告警到事件、事件到预案、预案到任务、任务到反馈的核心链路；
- 事件地址坐标、附件、参与单位、续报时间轴和升级/降级/终止/结案审批；
- 统一态势图、多事件并行、值班/领导/部门席位和大屏视图，以及核心业务数据实时刷新；
- 专业预案版本、模板和可解释匹配；
- 预案在线编辑、会签意见、修订对比和正式文档导出；
- 资源推荐与申请—审批—出动—到场—归队，库存原子记账、采购批次、有效期、盘点损耗、撤销冲销和库存预警；
- 复盘问题、责任单位、整改期限、提交复核和销号闭环；
- 风险数据字段差异、派单、确认、模拟回写和重试对账；
- 单元测试、浏览器端流程测试、GitHub Actions 和 Vercel 自动部署。

### 尚不能按“标书验收完成”表述

- 浙政钉统一认证及移动端；
- 三套原系统源码/数据库的真实裁剪、迁移和数据校验；
- IRS、应急数据仓、权威气象、视频、物联网、短信和语音正式接口；
- 信创产品兼容改造、政务云部署及信息技术应用创新符合性测评；
- 等保定级、差距整改、测评和备案；
- 真实数据条件下的性能、可靠性、安全、备份恢复和灾备验证；
- 6 个月实施计划、至少 1 个月试运行、培训、使用手册、验收报告和一年 7×24 运维组织。

因此，当前更准确的定位是：**已经从单文件演示发展为可联网、可持久化、具备多条业务闭环的投标产品原型；适合需求澄清、方案演示和继续研发，但还不是可直接宣称通过采购验收的正式政务系统。**

## 5. 后续优先顺序

1. **继续补齐可独立完成的产品细节**：值班班次冲突与审批、异步导出字段选择、任务超时后台调度、原预案附件预览、行政区划主数据和跨事件分析。
2. **建立接入工程规范**：API 网关、适配器契约、主数据编码、接口日志、重试、对账、数据质量和脱敏审计。
3. **拿到甲方条件后联调**：浙政钉、IRS/数据仓、台汛测站、视频、城市安全设备、短信和语音。
4. **开展迁移与信创专项**：盘点旧系统、制定迁移映射和回退方案，在目标政务云与信创软硬件环境验证。
5. **形成正式交付包**：等保材料、测试报告、部署运维手册、培训材料、试运行记录、验收矩阵和服务承诺。
