# 西湖区应急管理综合平台

## 一、项目总述

西湖区应急管理综合平台是面向统一门户、台汛监测、预案响应、指挥调度、应急资源、物资库存、风险普查、城市安全、应急值班和灾后复盘的综合产品。项目由原单文件投标演示改造为 Next.js 应用，使用 Supabase 提供身份认证、Postgres 数据持久化和行级权限控制，通过 Vercel 对外发布。

当前版本提供：

- 邮箱密码注册、登录和会话保持；
- viewer、member、admin 三类基础角色；
- 区级、部门、镇街、村社、工作组组织树及人员归属；
- 可停用账号、分配角色，创建/停用邀请码并自动加入指定组织；
- 事件、任务、风险工单的新增、查询、更新和删除；
- 任务与风险工单按人员或组织指派，接收人可查看并处理自己的待办；
- 关键操作日志和基础审计追溯；
- 根域名登录状态检测、独立登录页和登录后的综合门户；
- 按业务模块划分的子域名入口、跨子域登录共享和门户返回导航；
- Supabase 云端持久化；本地访客数据仅作为开发测试能力保留；
- JSON 数据导入、导出和错误反馈；
- Vitest、Playwright 和 GitHub Actions 自动化检查。
- 预案库、可解释规则匹配、人工启动及指令自动生成；
- 预案、版本和任务模板独立建模，支持草稿、送审、发布、作废和复制新版本；
- 预案匹配权重可配置，并展示类型、响应等级和关键词的逐项评分依据；
- 指令已读、文字/图片/文件/定位反馈、复核通过、退回补充、完成和通知渠道跟踪；
- 事件地址与坐标、参与单位、处置记录、附件和完整时间轴，以及升级、降级、终止、续报、结案审批；
- 事件、风险点、队伍、车辆、仓库、避灾场所和监测设备统一态势图，多事件并行切换及值班席/领导席/部门席/大屏视图；
- 预案在线编辑、会签审批意见、版本修订对比和 Word 兼容正式文档导出；
- 救援队伍、专家、车辆、装备和场所独立建模，可按区域与能力推荐，支持申请、审批、出动、到场、归队全过程；
- 仓库、物资、库存余额、采购批次、有效期、领用人、盘点、损耗、入库/出库/调拨单、审核记账和撤销冲销；
- 风险普查批次导入、字段差异、批量派单、回写重试与对账；
- 资源、库存和风险数据 Excel 导入导出；
- 台汛与城市安全统一设备台账、历史监测趋势、地图定位和在线率指标；
- 可配置阈值、重复告警合并、认领、复核、转事件及关闭处置闭环；
- 值班岗位、排班、日志、交接班和通讯录管理；复盘问题支持责任单位、整改期限、整改、复核和销号；
- 台汛监测与城市安全设备预警体验，模拟数据显著标识；
- 浙政钉、IRS、数据仓、短信、语音、视频、物联网和气象接入台账。
- 面向角色的应急工作台、优先待办、当前事件上下文和跨模块协同导航；云端事件、告警、任务、调度和整改状态通过 Supabase Realtime 自动刷新；
- 指挥任务搜索筛选、明确状态动作、时限/超时提示和结案前置校验；
- 值班交接工作台、事件时间线与灾后复盘草稿/审核归档；
- 监测数据来源、更新时间和陈旧状态标识，以及高风险操作二次确认；
- 键盘焦点、跳转主内容、移动端布局、动态提示等无障碍与响应式体验。

## 二、使用介绍

### 访问与登录

打开线上地址后，平台在服务端检测登录状态：未登录时只显示独立登录页，已登录时进入综合门户。综合门户中的业务卡片分别进入独立子域名；各子产品共享登录状态，并可返回综合门户。生产环境不开放匿名访客工作台。

### 团队成员

1. 使用本人邮箱和独立密码注册，填写团队邀请码。
2. 如系统要求验证邮箱，完成验证后回到平台登录，并再次填写邀请码完成权限激活。
3. `viewer` 只能查看获授权数据；`member` 可以维护自己创建或指派给本人/所属组织的任务；`admin` 负责组织、成员、邀请码和全局监督。
4. 账号停用后不再能访问业务数据；关键变更写入操作日志。

邀请码只以哈希形式保存在数据库，不写入 GitHub。如邀请码泄露，可在 Supabase 的 `team_invites` 表中将其 `active` 设置为 `false`。

### 本地开发

1. 运行 `pnpm install && pnpm dev`。
2. 如需更换 Supabase 项目，将 `.env.example` 复制为 `.env.local`，填写 Project URL 和 Publishable Key。
3. 新项目按文件名顺序执行 `supabase/migrations` 中的迁移。
4. 执行 `pnpm lint`、`pnpm test` 和 `pnpm build` 完成本地检查。

浏览器端仅使用 Supabase Publishable Key；数据访问权限由数据库 RLS 策略控制，不得把 secret key 或 service role key 写入前端、仓库或公开日志。

### 标准作业流程

事件处置、预案数字化、风险数据治理和资源库存保障流程见 [SOP 流程图](docs/SOP.md)。标书原文的产品化转译、逐项覆盖情况和正式交付缺口见 [标书需求覆盖矩阵](docs/TENDER-COVERAGE.md)。
